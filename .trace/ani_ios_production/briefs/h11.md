## Prerequisite 2 — essential purpose

"Snap, never wrong motion". Every visible frame is either the exact specified motion or a defined,
reported degradation. A failure inside the engine must leave the page exactly as the author wrote
it: byte-identical styles, no listener, no subscription, every promise resolved. A user callback
can never corrupt engine state.

Write every item test-first: a unit test or browser row that fails before the change.

1. **`layoutRuntime`** (§7.2), a module singleton exported from the package.
   - It provides `mode`, `setMode` and `onDiagnostic`.

     effects of §7.2.

   - Wire it to the React adapter if §7.3 requires it, and export it from
     `@freestylejs/ani-react/layout` only if the authority says so.
2. **The diagnostics stream** (§7.2).
   - Emit every code of the table where its row says, with the exact payload: version, scope id,
     run id, engine, action, element, reason and metrics.
   - Build no payload when nothing listens.

3. **Isolation** (§7.2, §9.2).
   - Diagnostic listeners and `onSnap` run after the engine's state is consistent, each inside its
     own `try`.
   - A throwing listener is reported as `callback-error` to the other listeners only, and is
     rethrown asynchronously in development.
4. **The transactional boundary** (§9.2).
   - `flush()` and every frame callback run inside one idempotent boundary with the five steps of

     diagnostic listener. It must be compiled out of production builds or be inert there, with no
     public export.
5. **Statuses and precedence** (§9.3). Add `'failed'` and `'disabled'` with the exact order. Test
   that every pair of statuses that can co-occur resolves to the earlier one.
6. **`maxParticipants`** (§7.1, §9.1).
   - Count connected participants before any read. Over the cap, the capture and the flush read
     nothing and the whole flush snaps with `'capped'` and `participant-cap`. Prove this with

   - Make `maxNodes` (the mover cap) emit `mover-cap`.
   - Add validation of both options (`ANI_INVALID_OPTIONS`).
7. **Rows L-OPS-1 and L-OPS-2** in a new browser module, `layout_ops`, in Chromium and WebKit
