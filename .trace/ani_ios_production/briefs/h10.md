# Helper brief H10 — P6 board core: the pure modules

You are helper H10 on ani board, a whiteboard and diagram tool in the class of FigJam, draw.io and
tldraw. You build its pure core: no DOM, no React. A later helper builds the rendering, the UI
and the e2e suite on your API. The orchestrator reviews every line and runs every gate, and the
Chief Justice judges the P6 checkpoint.

## Setup

- Work in your own git worktree. First run `git reset --hard 3bae50a`; worktrees can start from a
  stale base.
- Create the package `app/board` (`@freestylejs/ani-board`, private) per §2 of the authority. Add
  only the scripts and dev dependencies the pure core needs now: TypeScript, Vitest with jsdom,
  and `fake-indexeddb` as a dev dependency for B-PERSIST.
  - Install with `pnpm install`. The registry is reachable.
  - Commit the lockfile change.
- Match the repo's TypeScript and biome conventions: read `biome.json`, `tsconfig.json` and
  `packages/layout/tsconfig.json`. Biome needs `--vcs-use-ignore-file=false`.
- Wire `app/board` into the workspace's `pnpm ts:typecheck` and `pnpm test` (the root vitest
  config) the way the packages are wired.
- Never read anything from a directory named `ui-kit`. Never use sudo. Kill processes by PID only.

## Prerequisite 1 — authority

`app/board/ARCHITECTURE.md` is the single authority. Read all of it word by word, and §2–§8,
§10.1, §10.2 and §14 twice.

## Prerequisite 2 — essential purpose

The board is a tool a person chooses to use:
- direct manipulation is exact and instant;
- nothing the user did is ever lost: every transaction is atomic and validated, and undo is
  exact;
- every motion is either the exact specified motion or none.

Your modules are the ground truth the UI stands on. A wrong hit test, a lossy undo or a corrupt
save is the worst kind of defect.

## Prerequisite 3 — task boundary

### Thesis: what you build

Under `app/board/src/`, each module exactly as §2.1 describes, with the authority's types as
written:
1. **`model/`.**
   - The records of §3.1, typed exactly.
   - Ids from `crypto.getRandomValues`, with an injectable source for tests.
   - Fractional indices (§3.3).
   - The validator of every §3.4 invariant, with error paths.
   - Shape defaults per type.
2. **`geometry/`.**
   - Vectors, matrices, bounds, page transforms (§5.1).
   - Hit tests and the marquee (§5.2), snapping with guides (§5.3), pen simplification and outline
     (§5.4).
   - Straight and curved connector paths and endpoint clipping (§5.5). The elbow router and
     auto-layout belong to P7, but leave the module seams for them.
3. **`store/`.**
   - Transactions with the derived-state order, validation and patches (§4.1).
   - History with push, merge and skip, gestures, cancel, and the 500-entry cap (§4.2).
   - Selection and the entered group.
   - Subscriptions with changed ids (§4.3).
   - Groups (§3.4 rule 2, §6.1).
   - Connector re-routing on target change (§6.2), straight and curved routes only.
4. **`camera/`.** Everything in §7 except the animated changes: pan, zoom about a point, wheel delta
   modes, pinch, keyboard steps, fit to all and fit to selection with margins and the cap,
   screen–page mapping.
5. **`tools/`.**
   - The normalized `InputEvent` of §8.1.
   - Every tool state machine of §8.2: select (translate with Shift and Alt, resize with Shift,
     Alt and flips, rotate with snaps, marquee, nudge runs), hand, shape tools, sticky, text,
     frame, line and arrow with binding, pen.
   - The keyboard actions of §8.3 as pure commands on the store: align, distribute, group,
     z-order, lock, hide, duplicate, select all, Tab order.
   - The tools produce store transactions and camera changes only. Leave the text-measurement
     callback as an injected function.
6. **`persist/`.**
   - JSON serialization, import and export with validation (§10.2).
   - The IndexedDB autosave and library (§10.1): serialized saves, debounce, flush on hide, the
     recovery path and the failure banner state.

Tests, each written before its code. These are rows B-MODEL-1, 2, B-HIST-1, 2, B-GEO-1, 2,
B-CAM-1, B-TOOL-1, B-PERSIST-1 and B-FILE-1 of §14, with their exact assertions:
- property tests with a seeded generator;
- hand-computed geometry fixtures (write the arithmetic in the test).

### Antithesis: what you must not do

- No DOM in `model`, `geometry`, `store`, `camera` or `tools`. Only `persist/` touches IndexedDB.
- No runtime dependency beyond §2.
- Do not edit `ARCHITECTURE.md`. Where it is silent or ambiguous, report the sentence with your
  choice, and choose the most conservative reading.
- Do not build rendering, UI, motion or e2e.
- No placeholder, no TODO left in shipped code, no skipped test.
- Do not push, and do not touch any remote. Commit in your worktree with plain messages and no
  model names.
