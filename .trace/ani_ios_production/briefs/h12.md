# Helper brief H12 — P3b accessibility and adversarial validation

You are helper H12 on the ani layout engine. H11b (P3a) implements the runtime, diagnostics,
transactions, statuses and caps. You build the remaining P3 safety surface: accessibility, the
focus rule, model-based lifecycle fuzz, mutation tests and adversarial failure paths. The
orchestrator reviews every line and runs the deciding gates. The Chief Justice judges P3.

## Setup

- Work in your own worktree. Fetch and reset to the pushed P3a head (the commit that adds this

  ```sh

  git reset --hard origin/dev/ecstatic-ramanujan-1mjr9q
  ```

## Prerequisite 1 — authority

Read `packages/layout/ARCHITECTURE.md` §5.8 (inert follower, focus-in-follower), §6 (inert
ownership), §8 (accessibility contract), §9.1–§9.4 (degradation, transactions, precedence, reduced

`layout_ops` rows before designing the new probes.

## Prerequisite 2 — essential purpose

"Snap, never wrong motion" includes the accessible picture: no duplicate interactive target, no
focus theft, no corrupted state after a hostile lifecycle, and no silent failure path. A fuzz or
mutation test exists to make a real invariant fail when it is broken, not to inflate a count.

## Prerequisite 3 — task boundary

### Thesis: what you build

1. **Crossfade follower `inert`** (§5.8/§6): set on the exiting follower from the first crossfade
   frame; restore byte-identically on reversal, unmount, abort and dispose. Test with an authored
   `inert` value present and absent.
2. **Focus ownership** (§8): a keyed reorder and a held re-render keep `document.activeElement`;
   layout never moves focus or owns `tabindex`/roles/ARIA.
3. **Focus-in-follower** (§8): if focus is inside the exiting follower (flat-tree, through shadow
   roots), the crossfade is skipped for the pair, the lead appears at A, the follower exits under
   presence alone, and diagnostic `focus-in-follower` is emitted with action `none`. Add the row
   L-A11Y-1 in Chromium and WebKit.
4. **Model-based lifecycle fuzz** (§11.3): a pure seeded model generates capture, frame markers,
   flush, presented/unpresented scroll, layout change, detach/re-add, document change, `layoutKey`,
   take/move/release/cancel, reduced-motion toggles, kill switch, visibility and injected
   exceptions. Assert: no NaN; B is the capture box or the node is reported snapped; no read after
   the first write in a batch; one writer per property; every listener/marker/subscription released
   when idle; every handle terminal; every report resolves; styles/`inert` restored byte-identically.
5. **Mutation tests** (§11.3), each must fail a named row: consume an aged capture; skip the frame
   marker; use the predicted box instead of the measured one; drop the layout-size check; ignore
   `scrollend`; skip cleanup on abort; release with `dt ≠ 0`; merge motion field by field.
   Use the repo's existing mutation style; do not add a mutation framework that rewrites source.
6. **Failure-path fuzz / adversarial caps**: injected `measure`, `write`, `animate`, `onSnap` and
   diagnostic-listener exceptions; `maxParticipants` and mover-cap boundaries; status precedence
   pairs. Every path must end in `'failed'`/`'capped'`/`'disabled'` as the authority says, with
   byte-identical styles and no leaked listener/subscription.
7. **Docs.** Update the layout guide's accessibility and failure sections in the existing style.

### Antithesis: what you must not do

- Do not reimplement or weaken H11b's runtime, diagnostics, transaction or status code. If a
  safety gap is in H11b, report it with a failing probe; do not patch around it.
- Do not implement the P4 drive seam, WAAPI changes, or a new public API.
- Do not add a test that passes by construction, a broad `try/catch` that hides a failure, or a
  `knownFailure`.
- Do not edit `ARCHITECTURE.md`; report ambiguities with the exact sentence.
- No push, no remote. Commit with plain conventional messages and no model names.

### Synthesis: done means

- The new L-A11Y-1 row and the fuzz/mutation suites are green in Chromium and WebKit, with empty
  `knownFailures`; Firefox advisory or recorded environment exception.
- Unit, `pnpm ts:typecheck` and biome (0 errors) are clean.
- Every mutation is shown to fail the row it names; every fuzz seed reproduces deterministically.
- Final reply: worktree/branch/commits, files, the test that failed before each item, counts per
  suite/engine, ambiguities, deviations, residual risks.
