## Prerequisite 2 — essential purpose

"Snap, never wrong motion." A handoff from a list that is still scrolling must not fly from a box
that is no longer where the user sees it: it degrades to a presence enter. A slotted participant
must be planned under its true flat-tree parent, or its first frame is wrong.

## Prerequisite 3 — task boundary

### Thesis: what you build

1. **Closed-root ancestry (§4.6).**
   - The scope tracks the shadow roots that hold a participant: `getRootNode()` of each registered
     element, open or closed, keyed by host. A root is tracked at `add` and dropped with its last
     participant.
   - `flatParent` takes that registry. For a node whose parent element hosts a known root, the slot
     is the one in that root whose `assignedNodes()` holds the node. Otherwise the existing order
     applies.
   - Every walk uses the one primitive: the nearest participant, the containment tests, the
     WAAPI-nesting check and the dev warnings.
   - Unit tests cover open, closed and unknown-closed roots, nested roots, and a slot reassignment
     between flushes.
2. **Actively scrolling source (§5.8).**
   - **Listeners.** Use one passive capture-phase `scroll` and `scrollend` pair per event root (the
     `Document` and each `ShadowRoot` holding a participant). Arm them only while the scope has a
     shared (`layoutId`) participant and disarm them when it has none. Each event records its
     target and reads nothing.
   - **The degraded handoff.** A handoff, or a reparent of a participant, degrades when its
     departing node is inside an active container while the new lead is outside it. The lead does
     not fly: it enters as a presence enter, or appears at A when it has no presence.
   - **Reporting.** This is not a snap, so `report.snapped` does not change. Record the reason
     internally so that P3 can emit the `handoff-scroll-active` diagnostic. Until then, print a
     development warning once per scope.
   - **Clearing.** Only `scrollend` clears the active state; time never does. Where `scrollend` is
     unavailable (feature-test `onscrollend`), every handoff out of a container that has scrolled
     since the scope bound degrades.
   - **Viewport-fixed.** When the departing node is in the document scroller and the new lead is
     viewport-fixed (an `offsetParent` walk that ends at a fixed element, run on this path only),
     the lead is outside it.
   - **Unit tests.** Cover arming and disarming, the active, cleared and never-cleared states, the
     fallback without `scrollend`, the fixed-lead rule, the inside-to-inside case (no degradation)
     and the reparent case.
3. **React rows L-MEAS-5 (React 18.3 and 19).** Add them to the existing React layout browser
   modules, one case per sequence and per React version:
   - a time-sliced render scrolled between chunks, (a) with a participant in the committing slice:
     the first frame equals the last presented box within 0.5 px; (b) without: the §4.4 outcome
     (an aged or capture-less flush, with the exact `'stale'` set). Do not assert diagnostics;
     they land in P3;
   - a transition interrupted by an urgent update;
   - a Suspense fallback, then a reveal while scrolled;
   - two commits coalesced.

   Each frame is checked against the oracle or the measured presented box. If a sequence fails
   today, fix the engine (React glue or scope), not the row.
4. **Scroll anchoring (§11.4 S2, amended in 03d1b80; §6 `overflow-anchor`; §12).**
   - Implement the one-time probe and the Firefox fallback exactly as S2 states.
   - **Probe.** It runs once per document, at the start of the first flush that will write a pose,
     before its first rect read. It uses a fixed, hidden 10 × 10 scroll container: one `translate`
     write, a 1 px reflow, one `scrollTop` read. The container is removed in the same task, and
     its reads and writes are counted in stats.
   - **Fallback.** Where the probe says a transform moves the anchor, every driven participant
     that is not itself a scroll container gets `overflow-anchor: none !important`, written as an
     owned declaration in the same mutation as its first pose write and restored byte for byte at
     settle.
   - **Rows.** Write row L-MEAS-14 (a, b, c) in `layout_meas.ts`, in every engine. L_MEAS_2 must
     then pass in Firefox.
   - **Unit tests.** Cover the probe gating, the owned write and restore, and the exclusion of
     scroll containers.
5. **Known failures.** Make L_MEAS_10 and L_HAND_2 in `layout_meas.ts` pass in Chromium, Firefox
   and WebKit, then remove them from `knownFailures`. Do not edit the rows. If one disagrees with
