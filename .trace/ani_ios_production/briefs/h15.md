## Prerequisite 2 — essential purpose

The scene is the evidence surface. Its visual quality must be a credible iOS reproduction, and every
frame must be scored against the independent oracle. A scene that looks plausible but skips a
metric, hides a wrong frame, or passes by construction is worthless. "디테일이 생명."

## Prerequisite 3 — task boundary

### Thesis: what you build

1. Implement these §11.6 scenes as self-contained page modules in `bench/layout/page/scenes/`,
   using the public API only:
   - S-PHOTO (300-cell grid, 1.5-viewport scroll, square→4:3, image counter-scale, back)
   - S-ACC (React; row expand, second row mid-flight, first collapse, 0.5 px separators)
   - S-STACK (6-card fan-out, presence badges, collapse)
   - S-ISLAND (pill→card, size/radius/crossfade, reverse at 30%)
   - S-INSERT (React; 3 rows enter at content top under presence at 1.5 viewport scroll)
   - S-DELETE (React; exit + popLayout lift at presented box, second delete 100 ms later)
   - S-CARD/S-SEG visual-spec deviations from H14-25: close X, content fade timing, image decode,
     safe areas, S-SEG stage/label geometry — match the spec or record a scene contribution.
2. Follow `p5_scene_spec.md` exactly for canvas/viewport, DOM hierarchy, participant channels,
   typography, colors, radii, shadows, spring tokens, scripted sequence, interruptions and the
   expected oracle tracks. Position-pin non-participant text inside non-uniformly scaling surfaces.
3. Reuse the H14 harness: manual clock frame scoring, real-clock twin, independent oracle, G1–G13,
   shape checks, report JSON. Add each scene to the scene registry and the `--check` set.
4. Add a per-scene A-12 engine/floor ratio probe (non-deciding unless S-BULK) and the required
   focus/inert/status/restoration checks.
5. Iteration 1: run the full P2/P3 scene set in Chromium and WebKit, record every failing metric,
   worst frame/participant, and a root-cause hypothesis in `bench/layout/ITERATIONS.md`. Do not
   fix the engine; do not change a tolerance.
6. Negative controls: for each new scene/metric, a deliberate break that makes the metric fail.
7. Docs: scene table, visual references, exact parameters and known contributions.
