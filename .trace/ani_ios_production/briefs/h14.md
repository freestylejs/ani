# Helper brief H14 — P5a native-grade harness and calibration scenes

You are helper H14 on the ani layout engine. Build the certification instrument, not a demo:
`bench/layout/` must be able to fail a wrong frame. The orchestrator reviews every line and runs the
deciding measurement. The Chief Justice judges P5 only after the full scene set and iteration log.

## Setup

- Work in your own worktree. Fetch and reset to the pushed P4 head (the commit that adds this
  brief). Confirm L-DRIVE-1..6 are green before starting.
- Install if needed. The harness runs on the certification instrument:
  macOS 27.0.1 arm64, Node 24.19.0, pnpm 10.20.0, Playwright 1.55.0,
  `chromium_headless_shell-1187` / `webkit-2203`, Firefox advisory.
- No ports: Playwright request interception. COOP `same-origin`, COEP `require-corp`.
- Biome `--vcs-use-ignore-file=false`; no `ui-kit`, no sudo, no push.

## Prerequisite 1 — authority

Read `packages/layout/ARCHITECTURE.md` §11.1 (oracle), §11.5 (harness, cost gates, certification
instrument, required-work floor, measurement, aggregation), §11.6 (11 scenes and frame scoring),
§3, §5, §7 and §10. Read `bench/browser/` for conventions and `tests/browser/` for the manual clock,
frame helpers and oracle patterns. Read D8/D9 in `00_plan.md` and
`gate_amendment_20261028.md`.

## Prerequisite 2 — essential purpose

The harness is the judge of "iOS Native Grade". Its oracle must share no solver or `physics` code
with production. Its gates come from §11.5/§11.6 verbatim. A scene never passes by construction. A
harness that cannot fail is worthless: every metric needs a negative control that makes it fail.

## Prerequisite 3 — task boundary

### Thesis: what you build

1. **`bench/layout/`** TypeScript runner in the repo style: Node native type stripping, Playwright,
   request interception, no ports.
   - Options: `--engine chromium|webkit|firefox`, `--scene <glob>`, `--runs` (default 1 warm-up +
     5 measured fresh-process runs), `--out <file>`, `--compare <file>`, `--check`.
   - `pnpm bench:layout` and `--check` exit 1 on any gate miss after writing the report.
   - Report JSON includes the fingerprint, per-run statistics, medians, `g`, scene/metric worst
     frame/participant, and pass/fail.
2. **Fingerprint** §11.5 exactly. A mismatch makes the cost result `advisory`; frame-scoring gates
   still decide. Record the 1-minute load at start.
3. **Independent oracle**: closed-form timing curves and a high-order numerical spring integrator
   that does not import production `physics`/`solve`/`plan`. Unit-test it against hand-computed
   values. It must model each scene's scripted tracks independently.
4. **Frame scoring** on the manual clock: every §11.6 metric per participant per frame; report the
   worst value, frame and participant. Include oracle geometry error, first-frame continuity,
   edge-velocity continuity, spring fidelity, settle exactness, restoration, status/degradation
   correctness.
5. **Real clock and cost**: granularity `g`, one-frame or 20-frame samples, nearest-rank percentiles,
   per-run statistics and median-of-5. Implement the **required-work floor fixture** of §11.5:
   same DOM, exact §4.1/§4.3 reads/writes, no engine state, audited read/write counts. Implement
   the commit gate `median(engine)/median(floor) ≤ 2`, steady p95 ≤ 2 ms, sustained and held gates,
   exact read counts. The floor and engine run in the same process with the same warm-up/sample
   protocol.
6. **Negative controls**: one per metric, feeding a deliberately broken trace (0.1 px offset,
   velocity jump, leftover declaration, wrong status, wrong stale set, a floor with an extra read)
   and showing the metric/gate fails.
7. **Calibration scenes** (full quality, not placeholders): S-CARD and S-SEG, plus S-PHOTO if time.
   Realistic iOS geometry, typography, radius and spring parameters; viewable as a page; scripted
   on the manual clock with a real-clock twin. Build them with the public API only.
8. **Iteration 0** for the calibration scenes in Chromium and WebKit: record every failing metric,
   worst frame and root-cause hypothesis in `bench/layout/ITERATIONS.md`; do not fix the engine.
9. **Docs**: `bench/layout/README.md` with the exact commands, fingerprint, report schema, floor
   audit, negative controls and the "a harness that cannot fail is worthless" rule.

### Antithesis: what you must not do

- Do not edit `packages/*/src`, `tests/browser/` cases or `ARCHITECTURE.md`.
- Do not import production solver/physics into the oracle; do not call production code to compute
  expected frames.
- Do not change a gate or tolerance; where §11.6 is silent, report the sentence and take the
  strictest reading.
- Do not build a generic canvas/editor/product application; scenes are bounded iOS interactions.
- No placeholder scene that skips scoring; no `pending` except S-REORDER/S-SHEET before P4, and P4
  is already done, so they are not pending.
- No push/remote; commit plainly.

### Synthesis: done means

- Oracle/scoring/statistics unit tests and every negative control pass.
- `pnpm bench:layout --check` runs end to end in Chromium and WebKit, writes a report and fails on a
  negative control.
- Calibration scenes and iteration 0 exist; the report names the worst frame/participant.
- Typecheck/biome clean.
- Final reply: worktree/branch/commits, files, scene/metric table, floor audit, negative-control
  results, ambiguities, deviations, risks.
