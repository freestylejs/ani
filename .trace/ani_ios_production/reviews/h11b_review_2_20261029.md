## New defects

### N1 (S2) — late lead handoff without a track is falsely stale

`unmeasured` is cleared only for `action.kind === 'track' && handoffFrom !== undefined`. A valid
handoff whose box equals A or is below `threshold` produces action `none`; the node remains
`unmeasured`, is reported `'stale'`, receives `onSnap('stale')`, emits `capture-less-flush`, and
sets status `'stale'` even though the plan accepted the departing lead's box as B.

Fix: clear stale for any late lead for which the plan accepted a handoff, regardless of whether a
track is needed; or report against the accepted handoff box. Add same-box and below-threshold rows.

### N2 (S2) — `captureAdded()` reads after the cap

It does not check the current connected count/`maxParticipants` before `viewRect()`. A late mount
crossing the cap reads a rect, defeating the zero-read guarantee; the cap diagnostic's
`rectReads` metric is reset and reports 0.

Fix: count before `viewRect()`; over cap → skip the mount read and let `cappedFlush()` snap. Add a
React late-add crossing `maxParticipants` test with `stats.rects` and
`participant-cap.metrics.rectReads`.

### N3 (S2) — capped capture latching

§9.1's strict reading is latching: a capture that counted over `maxParticipants` must make the
flush read nothing and snap the whole scope. The fix made it per-pass; a capped capture followed by
a smaller flush now reads. Restore latching (`cap.capped` → `cappedFlush` regardless of current
count), update the test that asserts the non-latching path, and add a zero-read capped-capture →
smaller-flush test.
