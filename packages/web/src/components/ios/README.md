# Ani iOS interaction components

## Purpose and authority
Eight independently implemented, reusable React components exercise Ani against the eight Motion examples requested on 2026-11-04. `packages/core/src/API.md`, `packages/layout/ARCHITECTURE.md` v4 and `packages/layout/NATIVE_QUALITY.md` remain the engine authorities. This document governs this product surface only. It does not define new projection mathematics or silently enlarge the layout solver's supported geometry.

The main engineer owns implementation and tests; subagents are independent judges only. Original reference reconstruction is recorded in `.trace/ani_motion_ios_parity/`; publish-readiness repairs and cumulative judgments are in `.trace/ani_publish_readiness/`. These traces are evidence, not alternative runtime authorities.

## Reference evidence and limits
The reference inspection recorded on 2026-11-04 covered the provided official example pages and public marketing videos linked by the rendered `https://motion.dev/examples` catalog. At that inspection, seven examples' complete sources/live access were gated; **React AnimateView App Store was public**, including its complete displayed source and live example. A first blanket access classification was incorrect and was repaired following the Phase00 trial. That inspection did not have authenticated Motion account access. These are dated reference-access facts, not claims about the capabilities of a later execution session. No login gate was bypassed, premium source recovered, or source bundle reverse-engineered.

Therefore the visual preview and public tutorial are evidence for their observed states, not evidence for every hidden event branch, exact internal constants, or source equivalence. Full behavioral parity is **not certified**. An independent reconstruction must retain that distinction even when all its own tests pass. Physical iOS presentation/input is also separate from desktop Chromium/WebKit proof.

## Implementation contracts
- Each component works without the showcase router and accepts its own data/callbacks plus optional Ani `clock`. Instance ids are namespaced; two instances must not share layout identities or input state.
- Primary animation uses Ani public APIs only: layout for DOM geometry; core followers/timelines for numeric values, magnetic cursor, elastic effects and authored choreography. No Motion package, copied premium component, competing FLIP solver or component-owned rAF loop.
- Continuous pointer movement writes through Ani values, not React state every frame. The gesture layer owns pointerId/capture, timestamped recent velocity, cancellation and keyboard operation. Dispatched position is distinct from the velocity sample history: equal-resolution/final-up coordinates are retained, a clock regression discards speed history, and optional coalesced-input failure falls back to the dispatched event. Coalesced samples must belong to the same pointer id/type and dispatch time interval; their maximum displacement survives an out-and-back movement. Invalid terminal input cancels rather than activating stale input. Session ownership is cleared before terminal callbacks, capture is released even when callbacks throw, and a cleanup failure cannot replace the original callback error. Layout retains transform ownership on layout participants.
- Normalized numeric controls use finite bounds. `onValueChange` and `onValueCommit` report bounded proposals, not overshoot or a stale batched owner value. Controlled props remain authoritative. A release velocity is used only for an accepted proposal; same-event batched acceptance can consume it, while rejection and unrelated later owner changes cannot. Cancellation never triggers a primary action. Swipe thresholds use the final pointer-up position; moving back inside the full-swipe threshold before release does not activate the primary action.
- Controlled Exposure freezes its presented pose until a commit can decide acceptance. One local state update per release guarantees that decision even when the owner rejects without rerendering; pointer moves and animation frames do not update local React state. The commit consumes a release at most once, and only an enabled owner accepting the exact proposal receives its velocity. Quantization, rejection and disable use zero release velocity. A new capture, cancellation, keyboard request or reset invalidates an older pending release. Later external updates are ordinary target changes, never a replay of that release. No microtask deadline decides owner acceptance. Uncontrolled release remains immediate.
- Reduced motion retains direct manipulation but skips nonessential animated recovery/geometry; every component supports keyboard access and releases owned subscriptions/capture/listeners on unmount. Cursor hiding is scoped to its surface, never document-wide.
- App Store layout and View components share semantic content/styles only. The View component uses Ani's actual View Transition API, with explicit unsupported/reduced degradation, and never substitutes layout animation while calling it a native View Transition.
- Modal focus is contained, Escape/outside dismissal works, focus returns to the trigger, and background interaction is disabled while open. Folder uses one persistent native dialog/icon tree; the browser top layer owns modal isolation. App labels are position-only layout participants with independent opacity, so surface scale never enlarges visible labels. No global scrolling/cursor styles leak after teardown.
- Layout App Store retains its actual outgoing decoded card through the existing presence/shared-layout handoff. The first frame is painted by that retained bitmap, not a newly decoded replacement or a baked screenshot. Crop and bitmap are separate participants with reserved aspect geometry. The source is released after the handoff; descendants must be measurable before native modal promotion.
- Original image paths publicly documented by Motion's JS App Store tutorial (`/photos/app-store/a.jpg`, corresponding b/c/d artwork, `/authors/matt-perry.png`) are public visual assets, not executable reference code. Default assets are attributed and replaceable through props. Do not bake an entire UI screenshot into an interactive component.

## Acceptance
Tests must prove finite math/limits, state transitions, rapid reversals, actual pointer routing and release/cancel, keyboard and reduced-motion handling, multiple instances, lifecycle cleanup and the two distinct store backends. Browser tests use these actual components, not simplified twins.

Appearance is separately compared against the public reference recordings at declared viewport/state. A self-only test is not reference parity. Unobserved behavior, unmatched artwork/resolution, unknown timing, unavailable authenticated source, or missing device measurement stays explicitly unverified. Do not weaken v4 geometry/continuity tolerances or certify iOS from a screenshot/rAF proxy.

## Standalone route
`/ios` is an independent root layout, without the docs shell, theme provider, sidebar or global docs styles. It presents the eight actual reusable components, direct official references, optional side-by-side public preview, reset and test controls. A component-only view uses the same implementation for clean comparison; it must not change the component law or semantics.
