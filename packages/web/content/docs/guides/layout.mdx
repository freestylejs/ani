`@freestylejs/ani-layout` animates layout changes. You mark elements; when a change moves or resizes a marked element, it animates from where it was drawn to where layout put it. The React adapter, `@freestylejs/ani-react/layout`, does this on every commit without any call from you.

```sh
pnpm add @freestylejs/ani-core @freestylejs/ani-layout @freestylejs/ani-react
```

`@freestylejs/ani-layout` is an optional peer dependency of `@freestylejs/ani-react`. Only the `@freestylejs/ani-react/layout` entry needs it.

### How it works

-   **Before the change, capture.** Every render of a participant, a `LayoutGroup` or an `AnimatePresence` reads where the participants of its group are drawn now. React has not changed the DOM yet, so this is what the user sees.
-   **After the commit, flush.** One microtask per group, after every layout effect and before paint, reads where layout put each participant and starts an animation for every box that moved by at least `threshold` pixels (default 1).
-   **Frames do no reads.** Each frame computes every moving box from its two ends, parent before child, and writes only `translate` and `scale` (plus `opacity` for a shared-element crossfade and `border-radius` when `radius` is on). With the default `'raf'` engine, the animation runs on Ani's clock together with every other Ani animation; the optional [`'waapi'` engine](#compositor-engine) uses the document timeline.
-   **Both ends are what the user sees.** The start is the box as it was drawn, including any transform on screen (an animation in progress, a presence enter, a hover scale). The end is where the element will rest. An interrupted element therefore continues from where it is drawn. The default `'raf'` engine keeps nested participants exact at any depth; the optional [`'waapi'` engine](#compositor-engine) accepts only flat participants.
-   **Jump, never move wrongly.** An element the engine cannot animate exactly jumps to its final layout and is reported with a [reason](#when-an-element-jumps).

The first painted frame after a change shows the previous picture; the last frame is the real layout with your inline styles exactly as they were. A participant that mounts has no previous box: it appears where it lays out (give it an enter with [presence](#presence)), unless it takes over a [`layoutId`](#shared-elements). On the server nothing runs, and hydration never animates.

### Animate a list

Mark each item with `useLayout`. Nothing else is needed: the state change re-renders the items, and every item whose box changed animates.

```tsx
import { useLayout } from '@freestylejs/ani-react/layout'
import { useState } from 'react'

type Todo = { id: string; label: string }

function Item({ todo }: { todo: Todo }) {
    const ref = useLayout<HTMLLIElement>({ layout: 'position' })
    return <li ref={ref}>{todo.label}</li>
}

export function TodoList({ initial }: { initial: Todo[] }) {
    const [todos, setTodos] = useState(initial)
    return (
        <>
            <button
                type="button"
                onClick={() => setTodos((list) => [...list].reverse())}
            >
                Reverse
            </button>
            <ul>
                {todos.map((todo) => (
                    <Item key={todo.id} todo={todo} />
                ))}
            </ul>
        </>
    )
}
```

`useLayout(options?)` returns a ref callback. It is stable while the element stays in the same group, so it never re-attaches on its own. Pass `ref` in the options to forward the element to another ref as well.

### Options

| Option | Default | Meaning |
| :--- | :--- | :--- |
| `layout` | `true` | What animates; see [Modes](#modes). |
| `layoutId` | — | Shared identity; see [Shared elements](#shared-elements). |
| `layoutAnchor` | — | `{ x, y }`, each from 0 to 1. Keeps this point of the box on the same point of the parent participant; see [Anchored children](#anchored-children). |
| `layoutCrossfade` | `true` | Crossfade with an exiting element of the same `layoutId`. |
| `layoutDependency` | — | When given and `Object.is`-equal to its value at the previous flush, the element jumps to its new box instead of animating (not reported). Use it to animate only for the changes you name. |
| `radius` | `true` with a `layoutId`, else `false` | Keep the corners' on-screen radius while the box is scaled. Between two elements with one `layoutId`, the corners blend from one radius to the other unless either sets `radius: false`. |
| `motion` | — | `{ duration, delay, timing }` in seconds; see [Motion](#motion). |
| `ref` | — | Another ref that receives the element. |

Options are compared by effective value on every render: an inline object or an inline `timing.spring({ ... })` with the same values changes nothing. Only an effective change of `layout`, `layoutAnchor`, `radius` or `motion` restarts a running animation, from where the element is drawn.

#### Modes

| `layout` | Position | Size | Use it for |
| :--- | :--- | :--- | :--- |
| `true` | animates | animates | Surfaces: cards, panels, images. |
| `'position'` | animates | final size at once | Text and list rows. Under a parent that scales, the element is counter-scaled, so its content never stretches. |
| `'size'` | final position at once | animates | A box that grows in place. |

A size animation scales the element, and everything inside it that is not a participant scales with it. Mark text inside a resizing surface with `layout: 'position'` to keep its glyphs at their size:

```tsx
import { useLayout } from '@freestylejs/ani-react/layout'
import type { ReactNode } from 'react'

export function Panel({ open, children }: { open: boolean; children: ReactNode }) {
    const panel = useLayout<HTMLDivElement>({ radius: true })
    const title = useLayout<HTMLHeadingElement>({ layout: 'position' })
    return (
        <div ref={panel} className={open ? 'panel open' : 'panel'}>
            <h3 ref={title}>Details</h3>
            {open && <p>{children}</p>}
        </div>
    )
}
```

#### Motion

| Field | Default | Meaning |
| :--- | :--- | :--- |
| `duration` | `0.35` | Seconds. |
| `delay` | `0` | Seconds. Applies to an element at rest when the change happens. A moving RAF element starts at once and keeps its speed; a WAAPI retarget follows the compositor rule below and carries no speed. |
| `timing` | `timing.easeOut()` | A core timing function. |
| `type` + `bounce` | — | `{ type: 'spring', bounce }` selects the physical spring; `duration` is perceptual and `bounce` lies strictly inside (−1, 1). A layer with `timing` selects the timing kind. |

The timing must be stateless and must start with a finite slope. The default `'raf'` engine needs that slope to carry a moving element's velocity into the curve; WAAPI uses the same validated timing but retargets at rest. `timing.linear()`, `timing.bezier(...)`, the CSS presets and `timing.spring(...)` work. `timing.dynamicSpring(...)` and a bezier with `x1 = 0` and `y1 ≠ 0` throw a `TypeError` or `RangeError` with the code `ANI_INVALID_OPTIONS` as soon as you pass them. Like everywhere in Ani, `timing.spring` is fitted to `duration` (see [timing](/en/docs/core-api/timing)).

A participant's `motion` is merged by kind over the `motion` of its groups, outermost first: a layer that names `type: 'spring'`, `timing` or `type: 'timing'` selects the kind, a kind switch keeps only `delay`, and `duration`, `timing` and `bounce` override within the chosen kind.

```tsx
import { timing } from '@freestylejs/ani-core'
import { LayoutGroup, useLayout } from '@freestylejs/ani-react/layout'
import type { ReactNode } from 'react'

const springy = {
    duration: 0.5,
    timing: timing.spring({ m: 1, k: 300, c: 30 }),
}

export function Springy({ children }: { children: ReactNode }) {
    return <LayoutGroup motion={springy}>{children}</LayoutGroup>
}

export function Row({ label }: { label: string }) {
    // inside <Springy>: duration 0.5 and the spring from the group,
    // plus a delay of its own
    const ref = useLayout<HTMLLIElement>({ motion: { delay: 0.05 } })
    return <li ref={ref}>{label}</li>
}
```

### Shared elements

Elements with the same `layoutId` are one element to the user. On the default `'raf'` engine (the only engine that accepts `layoutId`), when the element that carries an id leaves and another one with the id is rendered, the new one starts from the box and speed of the one that left.

-   **Lead.** Per id, the newest mounted element that is not exiting leads. Two mounted, non-exiting elements with one id print a development warning; the newest leads and the other animates on its own.
-   **Handoff.** The new lead starts from the drawn box of the element it replaces: the live box of an element exiting under presence, or the box of a removed element, kept for `retain` seconds (default 1). A handoff out of an actively scrolling container is a presence enter instead; where the browser has no `scrollend` event (WebKit 26), that active state is never cleared by time, so such handoffs stay presence enters.
-   **Crossfade.** When the previous element is exiting under [presence](#presence) and the box moved, both draw at the lead's box while the lead fades in and the exiting element fades out, on the lead's curve. The lead fades in over the first half and the exiting element fades out only after it, so the pair never shows what is behind it. The exiting element stays invisible until presence removes it, and presence waits for the crossfade to end. `layoutCrossfade: false` on either element turns it off.
-   **Inert follower.** The exiting follower is `inert` from the crossfade's first frame, so there is one interactive and accessible target while the pair shares a box. Your own `inert` value, or its absence, is restored byte for byte when the element re-enters (a reversal), unmounts, or the run aborts or is disposed.
-   **Corners.** Unless either element sets `radius: false`, the corners blend from the radius the old element showed to the new element's own, on the same curve, so the shape changes with the box.
-   **Opacity.** If the exiting element's presence animates `opacity` itself, there is no crossfade and a development warning is printed. Animate opacity on a child instead.
-   **Focus.** If focus is inside the exiting follower, the pair does not crossfade: the new lead appears at its final layout, the follower exits under presence alone, and the `focus-in-follower` diagnostic is emitted with action `'none'`. Layout never moves focus; the author moves it.

A card that opens into a detail view, with the surface, the image and the title as three nested ids:

```tsx
import { ani, timing } from '@freestylejs/ani-core'
import {
    AnimatePresence,
    LayoutGroup,
    useLayout,
    usePresence,
} from '@freestylejs/ani-react/layout'
import { useState } from 'react'

type CardData = { id: string; title: string; image: string }

const cardMotion = {
    duration: 0.45,
    timing: timing.spring({ m: 1, k: 300, c: 30 }),
}

// An exit that changes nothing: presence keeps the detail mounted, and marks
// it as exiting, until the crossfade back to the card has ended.
const handoff = {
    present: { translateY: 0 },
    exit: ani({ to: { translateY: 0 }, duration: 0.1 }),
}

function Card({ card, onOpen }: { card: CardData; onOpen: () => void }) {
    const surface = useLayout<HTMLButtonElement>({
        layoutId: `card-${card.id}`,
    })
    const image = useLayout<HTMLImageElement>({ layoutId: `image-${card.id}` })
    const title = useLayout<HTMLSpanElement>({
        layoutId: `title-${card.id}`,
        layout: 'position',
    })
    return (
        <button ref={surface} type="button" className="card" onClick={onOpen}>
            <img ref={image} src={card.image} alt="" />
            <span ref={title}>{card.title}</span>
        </button>
    )
}

function Detail({ card, onClose }: { card: CardData; onClose: () => void }) {
    const presence = usePresence(handoff)
    const surface = useLayout<HTMLElement>({
        layoutId: `card-${card.id}`,
    })
    const image = useLayout<HTMLImageElement>({ layoutId: `image-${card.id}` })
    const title = useLayout<HTMLHeadingElement>({
        layoutId: `title-${card.id}`,
        layout: 'position',
    })
    return (
        <div ref={presence.ref} style={presence.style} className="overlay">
            <article ref={surface} className="detail">
                <img ref={image} src={card.image} alt="" />
                <h2 ref={title}>{card.title}</h2>
                <button type="button" onClick={onClose}>
                    Close
                </button>
            </article>
        </div>
    )
}

export function Cards({ cards }: { cards: CardData[] }) {
    const [openId, setOpenId] = useState<string | null>(null)
    const open = cards.find((card) => card.id === openId)
    return (
        <LayoutGroup motion={cardMotion}>
            <ul className="grid">
                {cards.map((card) => (
                    <li key={card.id} className="cell">
                        {card.id !== openId && (
                            <Card card={card} onOpen={() => setOpenId(card.id)} />
                        )}
                    </li>
                ))}
            </ul>
            <AnimatePresence mode="popLayout">
                {open && (
                    <Detail
                        key={open.id}
                        card={open}
                        onClose={() => setOpenId(null)}
                    />
                )}
            </AnimatePresence>
        </LayoutGroup>
    )
}
```

-   **Open.** The card unmounts and the detail mounts in the same commit. Each of the three ids starts from the card's boxes. The card is removed, not exiting, so there is no crossfade: the detail grows out of the card.
-   **Close.** The detail exits under presence and the card mounts again. The card starts from the detail's drawn boxes, and the two crossfade on the way back.
-   The grid cell stays rendered, so the grid keeps its shape while the card is open.
-   `layout: 'position'` keeps the title's text at its final size instead of stretching it.
-   Presence releases an exit after at most its exit duration plus one second (the `maxExitMs` watchdog). Keep the layout motion shorter than that, or raise `maxExitMs`.

### Accessibility

-   **Ownership.** Layout never changes DOM order, never moves focus, and never owns `tabindex`, roles or ARIA. A keyed reorder and a re-render while an element moves keep the same element and `document.activeElement`. Give focusable content its own accessible markup; layout only animates boxes.
-   **Crossfade followers.** An exiting crossfade follower is `inert` from the first fade frame, so the pair does not expose a duplicate interactive or accessible target while it crossfades. If focus is inside a live follower (for example after you removed its `inert`), the pair is ended at once: both opacities return, the presence hold releases, the follower exits under presence alone, and `focus-in-follower` is emitted. A follower that has already finished its fade is settled the same way, so it cannot remain an invisible interactive element. The authored `inert` attribute (present or absent, and its value) is saved and restored byte for byte on reversal, unmount, abort and dispose.
-   **Focus inside the follower.** When focus is inside the exiting follower (in the flat tree, through open and closed shadow roots), the crossfade is skipped for that pair: the lead appears at its final layout, the follower exits under presence alone, and `focus-in-follower` is emitted with action `'none'`. This also applies to a focus that arrives during a live fade or to a held follower: the pair is ended and both opacities return. Layout does not set `inert` in this case, because that would take focus away. Move focus to the new surface yourself, as part of the interaction that opened or closed it.
-   **Reduced motion.** The accessibility rules are unchanged; [reduced motion](#reduced-motion) only shortens or removes the motion.

For keyboard and screen-reader behavior of a shared open/close, keep the trigger and the close control in the rest of your markup, and move focus when the surface opens or closes. The layout engine's part is to keep the duplicate target out of the tab order and to leave focus where it was.

### Anchored children

`layoutAnchor` keeps a point of an element on the same point of its parent participant, on every frame. The parent participant is the nearest ancestor that is a participant of the same group; without one, the anchor is ignored and the element animates by its `layout` mode.

```tsx
import { useLayout } from '@freestylejs/ani-react/layout'

export function Stage({ wide }: { wide: boolean }) {
    const stage = useLayout<HTMLDivElement>()
    const dot = useLayout<HTMLDivElement>({
        layoutAnchor: { x: 0.5, y: 0.5 },
        motion: { delay: 0.8 },
    })
    return (
        <div ref={stage} className={wide ? 'stage wide' : 'stage'}>
            <div ref={dot} className={wide ? 'dot large' : 'dot'} />
        </div>
    )
}
```

When `wide` turns on, the stage grows. The dot's centre stays on the stage's drawn centre for the whole run, and the dot keeps its size until its own delay of 0.8 seconds has passed. If the anchor points do not coincide, the difference moves from its old to its new value on the dot's own curve.

### Groups

A participant with no `LayoutGroup` above it joins an implicit root group, one per clock and document, created on first use and disposed when its last participant leaves. All participants of a group are captured and flushed together, and share `layoutId`s.

`LayoutGroup` renders no DOM. The outermost `LayoutGroup` owns a group; nested ones join it:

-   `id` namespaces the `layoutId`s of the participants below it (`outer/inner/id`), so two lists with the same ids do not hand off to each other.
-   `motion` supplies defaults, merged field by field from the outermost group to the participant.
-   Group options are read from the outermost `LayoutGroup` only. A nested group that sets one prints a development warning.

| Group option | Default | Meaning |
| :--- | :--- | :--- |
| `clock` | `defaultClock` | Drives the default `'raf'` engine and supplies reduced motion to both engines. |
| `reducedMotion` | `'jump'` | See [Reduced motion](#reduced-motion). |
| `threshold` | `1` | Pixels a box must move to animate. |
| `maxNodes` | `300` | Visible moving elements per flush. Above it, the whole change jumps (`'capped'`). |
| `maxParticipants` | `2000` | Connected participants. Above it, capture and flush read nothing and the whole change jumps (`'capped'`). |
| `retain` | `1` | Seconds a removed `layoutId` element's box stays available for a handoff. |
| `onSnap` | — | `(element, reason) => void` for every element that jumped. The latest prop is always called; each call is isolated. |
| `engine` | `'raf'` | `'waapi'` runs flat position moves as compositor animations, smooth while the main thread is blocked. See [Compositor engine](#compositor-engine) for what it requires. |

A change of `clock`, `reducedMotion`, `threshold`, `maxNodes`, `maxParticipants`, `retain` or `engine` creates a new group, and running animations jump to their end. Define these values once, outside the component, and pass the same objects on every render.

### Compositor engine

`engine: 'waapi'` runs each move as a browser compositor animation (`Element.animate()`), so it stays smooth while the main thread is blocked. It is for flat lists and grids whose items only change position. Every requirement below is checked; the engine never falls back silently.

| Requirement | If it is not met |
| :--- | :--- |
| Every participant sets `layout: 'position'` | `add` / `set` throws `ANI_INVALID_OPTIONS` |
| No participant sets `layoutAnchor`, `layoutId` or `radius: true` | `add` / `set` throws `ANI_INVALID_OPTIONS` |
| No participant is inside another participant | `add` / `set` throws `ANI_INVALID_OPTIONS`; a nesting that appears later in the DOM makes that element jump (`'unsupported'`) |
| The browser supports the CSS `linear()` easing | The element jumps (`'unsupported'`) |

It also behaves differently from the default `'raf'` engine:

-   A move interrupted by a new change starts again from where it is drawn, at rest: it does not keep its speed.
-   The animations run on the document timeline, not on the Ani clock, so they ignore the clock's time scale. Reduced motion is still read from the clock at each change.
-   A change made while the main thread is blocked reads the drawn position on the main thread. The compositor may have drawn further, so the element can step back by the frames the main thread missed.
-   It writes no inline style. `finish()`, `dispose()`, removing an element and reduced motion cancel its animation.

### When a change animates

A commit animates when it renders a participant, a `LayoutGroup` or an `AnimatePresence` of the group: rendering is when the boxes are captured. A change that renders none of them, for example a reorder in a component whose items are memoized, changes the DOM without a capture, so it does not animate. In development, a `MutationObserver` prints one warning per group when that happens.

Two fixes:

-   Put the `LayoutGroup` inside the component that owns the state. Every render of that component renders the group.
-   Wrap the change in `useLayoutGroup().update(fn)`. It captures, runs `fn` inside `flushSync`, and flushes.

```tsx
import { useLayout, useLayoutGroup } from '@freestylejs/ani-react/layout'
import { memo, useState } from 'react'

const Tile = memo(function Tile({ label }: { label: string }) {
    const ref = useLayout<HTMLLIElement>({ layout: 'position' })
    return <li ref={ref}>{label}</li>
})

export function Board({ initial }: { initial: string[] }) {
    const [labels, setLabels] = useState(initial)
    const layout = useLayoutGroup()
    const reverse = () => {
        void layout.update(() => setLabels((list) => [...list].reverse()))
    }
    return (
        <>
            <button type="button" onClick={reverse}>
                Reverse
            </button>
            <ul>
                {labels.map((label) => (
                    <Tile key={label} label={label} />
                ))}
            </ul>
        </>
    )
}
```

`useLayoutGroup()` returns the nearest group's controls (the implicit root's when there is no `LayoutGroup`):

-   `update(fn)` resolves with the [report](#when-an-element-jumps) of the change.
-   `finish()` jumps every running animation of the group to its end.

Under `StrictMode`, the replayed renders, effects and ref callbacks keep one group and each participant's captured box. Transitions, deferred values and Suspense work as well: a render that React restarts in a later task captures again.

### Presence

`AnimatePresence` keeps a removed child mounted while it exits. It renders no DOM and never clones its children; each child that should animate calls `usePresence` with its motion.

| `AnimatePresence` prop | Default | Meaning |
| :--- | :--- | :--- |
| `initial` | `false` | Whether the children of the first render play their enter. |
| `mode` | `'sync'` | `'sync'`: exits and enters run together. `'popLayout'`: the exiting child leaves the flow at once, so its siblings move from the first frame. `'wait'`: an entering child waits until the exit has finished. |
| `custom` | — | Data passed to the children as `usePresence().custom`. |
| `onExitComplete` | — | `(key) => void` when a child's exit has finished and it is removed. |

`usePresence(motion, options?)` returns `{ ref, style, isPresent, custom }`. The motion has `present` (the resting values), a required `exit` node, and an optional `enter` node and `initial` values. Spread `style` after your own styles: it carries `initial` from the first render (also on the server) until the enter has finished, and the position of an exiting child under `popLayout`. `isPresent` is available for your own inert/disabled states; layout owns `inert` itself on an exiting crossfade follower (see [Accessibility](#accessibility)). For an exit you run yourself, `usePresenceControl()` returns `{ isPresent, safeToRemove }`; it gets no `popLayout` style and takes no part in a crossfade.

**`popLayout`.** In the render where a child stops being present, its box is measured relative to its containing block: the nearest ancestor that contains absolutely positioned elements (a positioned, transformed, filtered or contained ancestor), or the initial containing block. The commit lifts it to `position: absolute` at that box, before the flush, so the siblings are measured without it. No wrapper is required; a `position: relative` list keeps an exiting child inside the list's own scrolling and clipping.

A toast stack, where layout and presence share each element:

```tsx
import { ani, timing } from '@freestylejs/ani-core'
import {
    AnimatePresence,
    useLayout,
    usePresence,
} from '@freestylejs/ani-react/layout'
const toastMotion = {
    present: { opacity: 1, translateY: 0, scaleX: 1 },
    initial: { opacity: 0, translateY: 14, scaleX: 0.8 },
    enter: ani({
        to: { opacity: 1, translateY: 0, scaleX: 1 },
        duration: 0.3,
        timing: timing.easeOut(),
    }),
    exit: ani({
        to: { opacity: 0, translateY: 10, scaleX: 0.9 },
        duration: 0.2,
    }),
}

type ToastData = { id: string; text: string }

function Toast({ toast }: { toast: ToastData }) {
    const presence = usePresence(toastMotion)
    // `ref` forwards the element to presence: one stable ref callback (a
    // merged ref created inline would be new on every render)
    const ref = useLayout<HTMLLIElement>({
        layout: 'position',
        ref: presence.ref,
    })
    return (
        <li
            ref={ref}
            className="toast"
            style={presence.style}
            inert={!presence.isPresent}
        >
            {toast.text}
        </li>
    )
}

export function Toasts({ toasts }: { toasts: ToastData[] }) {
    return (
        <ul className="toasts">
            <AnimatePresence initial={false} mode="popLayout">
                {toasts.map((toast) => (
                    <Toast key={toast.id} toast={toast} />
                ))}
            </AnimatePresence>
        </ul>
    )
}
```

```css
.toasts {
    display: flex;
    flex-direction: column;
    gap: 8px;
}

.toast {
    transform-origin: 50% 100%;
    /* colors only: a transition on translate, scale or all makes layout jump */
    transition: background-color 0.2s;
}
```

A new toast plays its enter while the others slide to make room. A removed toast is lifted out of the stack, plays its exit where it was, and its siblings close the gap from the first frame. `useLayout({ layout: 'position', ref: presence.ref })` is a shorter way to give both hooks the element.

### Styles on a participant

With the default `'raf'` engine, layout and the other style writers own separate CSS properties as below. WAAPI is the exception: it writes no inline style and realizes its position-only move as a browser animation on `translate`.

| Property | Owner | Rule |
| :--- | :--- | :--- |
| `translate`, `scale` | Layout | Your own values, inline or from a stylesheet (Tailwind `translate-x-2`, `hover:scale-105`), are kept: layout composes its motion with them during a run and restores them exactly at the end. A change of them during a run applies when the run ends. |
| `transform` | Presence and Ani timelines | Never written by layout. Presence enters and exits, `useAniRef` and other Ani animations write here. |
| `transform-origin` | You | Read once per change. A size animation scales around it. |
| `opacity` | Presence and you | Layout writes it only for a `layoutId` crossfade pair. |
| `border-radius` | Layout when `radius` is on | Restored at the end of the run. |
| the `inert` attribute | Layout, only on an exiting crossfade follower | Saved when the crossfade starts (present or absent, and its value) and restored byte for byte on reversal, unmount, abort and dispose. Never set when focus is inside the follower. |
| `rotate`, skew | You | An element with them, or under a non-participant ancestor that rotates, skews or scales, jumps with `'unsupported'`. |

**CSS transitions.** A CSS transition on `translate`, `scale` or `all` would animate layout's own writes, so the element jumps with `'unsupported'` and a development warning. Tailwind's `transition` and `transition-all` include them; use `transition-colors`, `transition-opacity` or a `transition-property` list without them. A running CSS animation of `translate` or `scale` jumps the same way.

### Interruption

With the default `'raf'` engine, a change while elements are moving does not wait for them and does not restart them from scratch. Each element whose target moved starts its new animation from where it is drawn, with its current velocity, and skips its `delay`. Elements whose target did not move keep their running animation untouched, so an unrelated re-render cannot restart anything. A change of `layoutId`, `layoutCrossfade` or `layoutDependency` alone never restarts a running animation. With `'waapi'`, the compositor-engine rule above applies instead: a retarget starts from where it is drawn, at rest.

For `'raf'`, the carried velocity bends the start of the new curve and fades out by its end. It keeps the motion continuous; it is not spring physics.

### Direct manipulation

A participant can be taken as the user's finger. `take` returns a handle whose `move` places the
element's drawn origin at the take point plus an offset, and whose `release` hands it back with an
incoming velocity:

```ts
import { createLayoutGroup } from '@freestylejs/ani-layout'

const group = createLayoutGroup()
const card = document.querySelector<HTMLElement>('#card')!
group.add(card, { layout: true })

const take = group.take(card) // held; throws unless the element can be driven
take.move({ x: 12, y: -4 }) // view-space CSS px from the take point
take.release({ x: 0, y: 900 }) // px/s; default 0
// take.cancel(): back to the slot with zero velocity
```

```tsx
import { useLayout, useLayoutDrive } from '@freestylejs/ani-react/layout'

function Card() {
    const ref = useLayout<HTMLDivElement>()
    const drive = useLayoutDrive()
    return (
        <div
            ref={ref}
            onPointerDown={(event) => {
                const element = event.currentTarget
                const handle = drive.take(element)
                const origin = { x: event.clientX, y: event.clientY }
                const move = (e: PointerEvent) =>
                    handle.move({ x: e.clientX - origin.x, y: e.clientY - origin.y })
                const end = () => {
                    window.removeEventListener('pointermove', move)
                    window.removeEventListener('pointerup', end)
                    handle.release()
                }
                window.addEventListener('pointermove', move)
                window.addEventListener('pointerup', end)
            }}
        />
    )
}
```

The example is only the wiring: pointer capture, `pointerId`, `touch-action`, velocity estimation,
keyboard operation and announcements belong to your gesture layer. Map `pointercancel` and
`lostpointercapture` to `cancel()`.

-   **The hold.** The drawn origin is the take point plus the offset every frame, under a scroll, a
    live ancestor scale, sticky positioning (the element or an ancestor) and a re-layout. The only
    read a frame adds is one rect per held element, in the clock's read phase before any write; a
    size change also verifies support and the animated-owned probe: a running CSS animation or
    transition on `translate`/`scale` on the held element, a participant ancestor, or any element in
    the held subtree invalidates with `unsupported-geometry`. A box-preserving 180° rotation/zoom
    that the support check cannot classify is a residual risk: the check may invalidate the hold.
    `stats.rects` counts the reads; `stats.holds` counts every live hold (`held`, `released` and
    `cancelled` until it finishes or is invalidated).
-   **Size and descendants.** The held element's size keeps its track under one hold-specific
    tolerance (0.5 px): a supported re-layout is taken into the hold, a sub-threshold difference is
    snapped, and release always reaches its finish. Its participant descendants ride one inherited
    displacement `h(t)` with their own residuals, so their geometry relative to the held element
    does not depend on how fast `h` decays. The release velocity enters exactly once, through the
    held node's origin track.
-   **States.** `held`, `released`, `cancelled`, `invalidated`. `release`/`cancel` are terminal and
    idempotent; a `move` after a terminal state is a no-op with one development warning per handle.
    Non-finite offsets and velocities throw `ANI_INVALID_OPTIONS` before any state change. A hold
    invalidated by removal, `ownerDocument` change, `layoutKey`, `dispose()`, `finish()`, the kill
    switch, a failed held read or an internal abort follows that event's rule and stops reading.
    The authored inline style is restored byte for byte. A `take` during a landing settles the old
    landing at its current drawn box, invalidates the old handle and starts a new hold from it.
-   **Reduced motion.** The held phase is direct manipulation: `move` stays 1:1 and a policy change
    while held never ends the hold. The policy at `release`/`cancel` decides the landing: `'jump'`
    lands at A with no motion, `{ maxDuration }` clamps, `'ignore'` plays in full. A release that
    finds no reduced-motion fit becomes `released` and lands at A (a reduced jump); a refused spring
    emits `spring-timeout` and snaps. A release that finds no fitting path emits the typed
    `reduced-no-fit` diagnostic and lands at A. Under `'jump'`, a flush while held or landing
    settles every descendant residual at its own A. A release with no layout change springs back to
    the slot.
-   **Admission and limits.** An exiting crossfade follower is rejected with a `drive-rejected`
    diagnostic. An element belongs to at most one live group; adding it to a second throws. The
    ancestor/descendant hold exclusion is scope-local: a cross-scope nested hold is allowed, and a
    driven cross-scope child does not ride the other group's `h`. Held nodes and their riders count
    as visible movers for `maxNodes`; exceeding it invalidates the holds and reports `'capped'`.
    The kill switch wins over the `'waapi'` precondition: `take` returns an invalidated handle under
    the switch, and otherwise the `'waapi'` engine cannot take a hold. A `take` before an unflushed
    layout uses its own rect/computed reads; unsupported current geometry throws. `onSnap` lists
    each held node and rider with reason `'capped'`.

`useLayoutDrive()` returns a dispatcher for the same port. Its `take(element)` routes to the live
`LayoutGroup` that owns the registered element, otherwise to the implicit root of its document, and
throws `ANI_INVALID_OPTIONS` when no scope owns it. A StrictMode same-task ref detach and re-attach
preserves a live hold, just as it preserves registration. The gesture layer maps `pointercancel`
and `lostpointercapture` to `cancel()`, so a cancelled gesture never becomes a release; a
box-preserving 180° rotation/zoom shares the documented support residual risk above.

### Reduced motion

The preference comes from the group's clock (by default `matchMedia('(prefers-reduced-motion: reduce)')`) and is read at every flush, so a change applies at the next commit, also to elements that are still moving.

| `reducedMotion` | Behavior |
| :--- | :--- |
| `'jump'` (default) | Nothing animates. Running animations finish at once; RAF leaves no clock subscription and WAAPI leaves no browser animation. The report's status is `'reduced'`. |
| `{ maxDuration }` | Delay and duration are scaled down so that each animation fits in `maxDuration` seconds. Shorter ones are untouched. |
| `'ignore'` | Animations play in full. |

```tsx
import { LayoutGroup } from '@freestylejs/ani-react/layout'
import type { ReactNode } from 'react'

// defined once: a new object on every render would create a new group
const reducedMotion = { maxDuration: 0.2 }

export function App({ children }: { children: ReactNode }) {
    return <LayoutGroup reducedMotion={reducedMotion}>{children}</LayoutGroup>
}
```

Presence has its own `reducedMotion` option (`usePresence(motion, { reducedMotion })`), with the same policies and the same `'jump'` default. See [Reduced motion](/en/docs/guides/reduced-motion) for how the preference is read and tested.

### When an element jumps

Anything the engine cannot animate exactly jumps to its final layout. Each change resolves a report, `{ status, snapped }`, from `useLayoutGroup().update(fn)` or the vanilla `flush()`. Every element that jumped is listed in `snapped` and passed to `onSnap`.

| Condition | Effect | Reason |
| :--- | :--- | :--- |
| Both boxes are outside the viewport (plus 10 %) | That element jumps, and does not count toward `maxNodes` | `'culled'` |
| More than `maxNodes` visible elements move, or more than `maxParticipants` are connected | The whole change jumps | `'capped'` |
| `rotate` or skew; a non-participant ancestor that rotates, skews or scales; a CSS transition or animation on `translate`/`scale`; zero size; `display: contents` or `inline`; a size change beyond 50×; a spring settling after 10 s | That element and its participants jump | `'unsupported'` |
| No valid capture: none was taken, or it aged past a frame (taken in an earlier task's frame, or inside an animation frame) | Elements appear at their final layout; running animations keep going, moved with their layout. Elements that may have jumped by `threshold` or more are listed | `'stale'` |
| Reduced motion with `'jump'` | Everything jumps | `'reduced'` |
| The layout runtime's kill switch is on | Every mover jumps, at the next flush and synchronously while running | `'disabled'` |
| An internal exception aborts a flush or frame | Every owned declaration and the crossfade follower's `inert` are restored byte-identically, holds release, listeners and markers disarm, and every affected element is listed | `'failed'` |

`'unsupported'`, `'capped'` and `'stale'` print one development warning per group, naming the cause. `'culled'`, `'reduced'`, `'disabled'` and `'failed'` stay silent, and `'failed'` is reported through `internal-error`.

| `status` | When |
| :--- | :--- |
| `'failed'` | An internal exception aborted the run; styles and `inert` are restored and every affected element is listed as `'failed'`. |
| `'disposed'` | The group was disposed or unmounted, or every element of the change was removed. Inline styles are restored. |
| `'disabled'` | The runtime's kill switch was on. |
| `'capped'` | More than `maxNodes` visible elements moved, or more than `maxParticipants` are connected: everything jumped. |
| `'interrupted'` | A later change retargeted one of its elements. Its other elements keep running. |
| `'ended'` | Every element of the change settled, or `finish()` was called. |
| `'reduced'`, `'stale'` | Everything jumped (reduced motion), or the change had no valid capture and nothing animated. |
| `'no-change'` | Nothing moved. |

Statuses resolve in exactly that order (§9.3); `'reduced'`, `'stale'` and `'no-change'` apply only when no track ran.

### Runtime and diagnostics

`layoutRuntime` is a module singleton from `@freestylejs/ani-layout`:

```ts
import { layoutRuntime } from '@freestylejs/ani-layout'

const stop = layoutRuntime.onDiagnostic((event) => console.log(event))

// remote config: stop every layout motion on the page now
layoutRuntime.setMode('snap')

// later: plan normally from the next flush
layoutRuntime.setMode('animate')
stop()
```

The kill switch is synchronous in every explicit and implicit group: live tracks finish at identity with their styles restored, P3 crossfade/presence holds finish as a completed fade, drive holds are invalidated and restored, and pending reports resolve `'disabled'` with reason `'disabled'`. Later movers snap `'disabled'`. It is distinct from reduced motion.

`onDiagnostic` returns an unsubscribe. Payloads are built only when a listener exists, so the stream costs nothing when unused; it also works in production builds. Every listener runs after the engine's state is consistent, each inside its own `try`. A throwing listener is reported as `callback-error` to the other listeners only, never back to itself and never recursively, and is rethrown asynchronously in development. `onSnap` runs after the flush's diagnostics and is isolated the same way. A capture begun inside a clock frame prints the §4.1 development warning at capture; the flush that consumes the aged capture emits one `capture-aged` event per reported node (or one element-less event when none is reported).

```ts
import type { SnapReason } from '@freestylejs/ani-layout'

interface LayoutDiagnostic {
    readonly version: 1
    readonly code:
        | 'capture-less-flush'
        | 'capture-aged'
        | 'measurement-unsupported'
        | 'unsupported-geometry'
        | 'handoff-scroll-active'
        | 'spring-timeout'
        | 'participant-cap'
        | 'mover-cap'
        | 'document-mismatch'
        | 'runtime-disabled'
        | 'focus-in-follower'
        | 'drive-rejected'
        | 'reduced-no-fit'
        | 'callback-error'
        | 'internal-error'
    readonly scope: number // stable per group for the page's lifetime
    readonly run: number | null
    readonly engine: 'raf' | 'waapi'
    readonly action: 'none' | 'snap' | 'enter' | 'finish' | 'abort'
    readonly element?: HTMLElement
    readonly reason?: SnapReason
    readonly metrics: {
        readonly participants: number
        readonly rectReads: number
        readonly styleReads: number
        readonly springSettleMs: number | null
    }
    readonly error?: unknown
}
```

A flush and every frame callback run inside one transactional boundary. On an internal exception the engine restores every owned declaration and the crossfade follower's `inert` byte-identically, cancels browser animations, clears pending writes, invalidates holds, releases presence holds, disarms the frame marker and listeners, stops the clock subscription, resolves every affected report `'failed'` and emits `internal-error` with action `'abort'`. A failed report lists only the participants the transaction touched and the affected run nodes; the style and `inert` restore remains conservative for the whole scope. `flush()` never rejects.

`focus-in-follower` is a diagnostic, not a jump: no element is added to `snapped` and `onSnap` is not called. It is emitted when the crossfade is skipped because focus is inside the exiting follower (see [Accessibility](#accessibility)).

Invalid options (an unknown key, a negative duration, an anchor outside 0–1, a stateful timing) throw a `TypeError` or `RangeError` with the code `ANI_INVALID_OPTIONS` when they are passed, never inside a frame.

### Limits

-   The default `'raf'` layout engine runs on the main thread, on Ani's clock, so it does not advance on screen while the main thread is blocked. The optional [WAAPI engine](#compositor-engine) is the gated compositor-smooth exception.
-   The drive seam ([Direct manipulation](#direct-manipulation)) is layout's side only: pointer
    capture, `pointerId`, `touch-action`, velocity estimation, keyboard operation and announcements
    belong to your gesture layer. A re-render during a track is not a drive hold.
-   Capture reads the DOM during render. These are reads only, but when styles changed since the last layout they force one.
-   A change that renders no participant, `LayoutGroup` or `AnimatePresence` does not animate (see [When a change animates](#when-a-change-animates)).
-   Text inside an element that scales is re-rasterized and can look soft until the animation ends. Use `layout: 'position'` on text.
-   A change of your own `translate` or `scale` during a run applies when the run ends, as one jump.
-   A presence `transform` that animates during a layout run moves the element and its participants on top of their layout motion.
-   A box never shrinks below one pixel; a fast element headed there loses that part of its speed.
-   Not supported: 3D transforms, rotation and skew, SVG and inline elements, pointer capture and velocity estimation (the gesture layer owns those; layout provides the drive seam), scroll-linked layout without a scroll driver, shadow correction and curved paths.

### Vanilla API

Without React, `createLayoutGroup` from `@freestylejs/ani-layout` gives the same engine. You call the capture and the flush.

```ts
import { createLayoutGroup } from '@freestylejs/ani-layout'

const list = document.querySelector<HTMLUListElement>('#list')!
const group = createLayoutGroup({ motion: { duration: 0.3 } })

const removes = [...list.querySelectorAll<HTMLLIElement>('li')].map((item) =>
    group.add(item, { layout: 'position' })
)

// capture → mutate → flush
const report = await group.update(() => {
    list.prepend(list.lastElementChild!)
})

// or the same three steps yourself
group.capture()
list.append(list.firstElementChild!)
await group.flush()

for (const remove of removes) remove()
group.dispose()
```

| Member | Meaning |
| :--- | :--- |
| `add(element, options?)` | Registers a participant and returns an idempotent remove function that restores its styles. |
| `set(element, options)` | Replaces a participant's options. |
| `capture()` | Reads the boxes before a change, where they are drawn. Repeated calls in the same task reuse the reading; a call in a later task reads again. The reading is valid until the next frame. |
| `flush()` | Reads the boxes after the change and starts the animations. Resolves the report. |
| `update(mutate)` | `capture()`, `mutate()`, `flush()`. A throwing `mutate` discards the capture and rethrows. |
| `finish()` | Jumps every running animation to its end. |
| `dispose()` | Cancels everything and restores every style the group wrote. |
| `stats` | `{ captures, reads, rects, offsets, styles, probes, parents, tracks, holds }`: `reads` is `rects + offsets + styles` (rects, layout-size pairs and computed styles); `probes` counts the one-time scroll-anchoring probe, `parents` the `offsetParent` reads of the viewport-fixed test. |

`createLayoutGroup(options?)` takes the group options of the table in [Groups](#groups) plus `motion`. `createPresence(element, motion, options?)` is the presence handle behind `usePresence`: `enter()`, `exit()` and `dispose()`. A participant inside an exiting presence element takes part in a `layoutId` crossfade.

`layoutRuntime` and its `LayoutDiagnostic` payload are exported from `@freestylejs/ani-layout`; see [Runtime and diagnostics](#runtime-and-diagnostics).

### View Transitions

For discrete swaps such as route changes, use the browser's View Transitions instead:

```ts
import { shareElement, viewTransition } from '@freestylejs/ani-layout'

const hero = document.querySelector<HTMLElement>('#hero')!
const unshare = shareElement(hero, 'hero-42')

const result = await viewTransition(
    () => {
        document.body.classList.toggle('detail')
    },
    { share: ['hero-42'], motion: { duration: 0.3 } }
)
unshare()
```

-   `viewTransition` runs the update exactly once in every path and resolves `'finished'`, `'skipped'`, `'interrupted'`, `'yielded'`, `'unsupported'` or `'reduced'`.
-   Only the ids in `share` get a `view-transition-name`, and only for this transition.
-   Without browser support the update runs without a transition and resolves `'unsupported'`.
-   `retimeViewTransition(motion, names?)` retimes the browser's transition animations.

Use layout animation, not View Transitions, for reorders, accordions, toasts and anything that can be interrupted.
