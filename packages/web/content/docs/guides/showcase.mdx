Ani is at its best when a single description drives many realizations. This demo
is deliberately small, but it uses the full V2 stack: an immutable tree, a
single clock, one `rafGroup`, a per-target `from`, and a stagger that turns the
same plan into a wave.

## What you are looking at

- **Description.** `tree` is an immutable `sequence` of two `ani` nodes. It
  contains no DOM, no values, and no time. It can be replayed forever.
- **Time.** The group subscribes to the shared clock once. Every target sees
  the same frame time; the stagger only shifts each target's local time.
- **Realization.** `group.bind(tiles)` creates one writer per tile. The group
  evaluates the plan once per distinct `(offset, from)` pair and writes the
  changed declarations in the commit phase.
- **Replay.** The button does not rebuild the tree. It calls `play()` again with
  a new `from(index)` function, so the same description produces a different
  scatter.

```typescript
import * as a from '@freestylejs/ani-core'

type Tile = {
    opacity: number
    scale: number
    translateX: number
    translateY: number
    rotate: number
}

const COLS = 12
const tree = a.sequence([
    a.ani({
        to: { opacity: 1, scale: 1.06, translateX: 0, translateY: 0, rotate: 0 },
        duration: 0.45,
        timing: a.timing.easeOut(),
    }),
    a.ani({
        to: { opacity: 1, scale: 1, translateX: 0, translateY: 0, rotate: 0 },
        duration: 0.25,
        timing: a.timing.easeInOut(),
    }),
])

const group = a.rafGroup(tree, {
    stagger: (i) => (i % COLS) * 0.018 + Math.floor(i / COLS) * 0.045,
})

// In the live demo: group.bind(tiles) before play().
group.play({
    count: 36,
    from: (index): Tile => {
        const col = index % COLS
        const row = Math.floor(index / COLS)
        return {
            opacity: 0,
            scale: 0.5,
            translateX: (col - (COLS - 1) / 2) * 10,
            translateY: (row - 1) * 16,
            rotate: 0,
        }
    },
})

// The owner releases the group when the view goes away.
group.dispose()
```

## Why this is the point

Most animation code makes the element the unit of work: one element, one
timeline, one subscription. Ani makes the **description** the unit of work and
lets the realization fan out. The same tree can drive one element, 36 tiles, or
5,000 rows; the cost model is properties and distinct target states, not the
number of segments in the tree.

If this looks like a lot of machinery for a grid, that is the honest trade-off:
it is more concept than a one-line hover effect. In exchange, the choreography
is a value you can reuse, test, replay, and move between the RAF and WAAPI
engines without rewriting it.

- [rafGroup](/en/docs/core-api/group) — one plan, N targets
- [clock](/en/docs/core-api/clock) — one frame loop, read/update/commit
- [timing](/en/docs/core-api/timing) — the easing used above
