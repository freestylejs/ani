---
title: clock (AnimationClock / createClock)
description: The frame loop that drives timelines. Use the shared default clock, or create independent clocks for tests and isolated engines.
---

A **clock** calls `update(dt)` on every subscribed timeline once per animation frame. A timeline subscribes while it is `PLAYING` and unsubscribes when it pauses, ends, resets or is disposed.

### Example

```typescript
import { a, createClock } from "@freestylejs/ani-core";

// Independent clock that you drive yourself (tests, replays, workers).
let now = 0;
let pending: ((t: number) => void) | null = null;

const clock = createClock({
  requestFrame: (cb) => { pending = cb; return 1; },
  cancelFrame: () => { pending = null; },
  now: () => now,
});

const timeline = a.dynamicTimeline(a.ani({ to: { x: 100 }, duration: 1 }), clock);
timeline.play({ from: { x: 0 } });

now += 500;
pending?.(now); // one frame, 500 ms later (dt is clamped, see below)
console.log(clock.size); // 1 subscriber
```

### Usage & Concepts

#### The default clock

Timelines use one shared process-wide clock unless you pass another. It runs **one** `requestAnimationFrame` loop no matter how many timelines play, and it stops the loop when the last timeline leaves.

```typescript
import { AnimationClock } from "@freestylejs/ani-core";

AnimationClock.configure({ lagThreshold: 1 }); // tune the shared clock's time model
AnimationClock.reset();       // dispose the shared clock (tests, hot reload)
AnimationClock.create().size; // number of timelines currently driven
```

#### Guarantees

-   **One pending frame at most.** A re-entrant `subscribe` / `unsubscribe` never creates a second loop.
-   **Three phases per frame.** Every tick runs **read**, then **update**, then **commit** over all subscribers, so layout reads and DOM writes never interleave. See [Frame phases](#frame-phases).
-   **Per-tick snapshot.** A timeline subscribed during a tick (in any phase) first runs on the **next** tick. One unsubscribed before its update ran gets neither `update` nor `commit` in that tick.
-   **Progress since subscribe.** The first update of a new subscriber advances by the time elapsed since it subscribed, not by the time since the previous frame.
-   **Error isolation.** A callback that throws, in any phase, does not stop the others or the next frame. The error goes to `onError` when given, otherwise it is rethrown asynchronously. The subscriber stays subscribed unless it unsubscribes itself.
-   **Self-healing.** `subscribe` re-arms the loop when the environment dropped the pending frame (for example a fake rAF reinstalled). A pending frame older than one second is treated as lost.
-   **No frame source, no work.** Without `requestAnimationFrame` (server rendering, plain workers) `subscribe` is a silent no-op and the subscriber is not retained. See [SSR](/en/docs/guides/ssr).

#### Frame phases

A subscriber implements `update` and may add `read` and `commit`. The rule: **read in `read`, compute in `update`, write in `commit`.**

```typescript
clock.subscribe({
  read() { /* measure layout, sample inputs; no DOM writes */ },
  update(dt) { /* advance by dt seconds and compute; no DOM access */ },
  commit() { /* write this frame's results to the DOM */ },
});
```

Each frame runs the phases in order over the same snapshot of subscribers:

1. **Read:** first the one-shot callbacks queued with `clock.read(fn)` (FIFO), then `read()` of every subscriber that has one.
2. **Update:** `update(dt)` of every subscriber that is still subscribed.
3. **Commit:** `commit()` of every subscriber whose `update` ran in this tick, even if it unsubscribed during the tick, so a timeline that ends in this frame still writes its final value.

A subscriber with only `update` keeps working unchanged. `clock.read(fn)` arms an idle loop and runs `fn` once, in the next frame before any update; callbacks queued during a tick run in the following tick, and a queued callback does not keep the loop alive afterwards. Without a frame source it is a silent no-op.

#### Frame time: lag smoothing

The gap between two frames is turned into animation time with one rule:

| Gap since the previous frame | Treated as | Animation advances by |
| :--- | :--- | :--- |
| during which the page was hidden (a `visibilitychange` event fired while `hidden` was `true`), whatever its length | **suspension**: the tab was hidden | one ordinary frame (the latest gap of at most 50 ms; 1/60 s before any) |
| up to `lagThreshold` (default 0.5 s) | **jank**: the page is visible but busy | the real elapsed time |
| above `lagThreshold` | **suspension**: hidden tab, debugger, sleep | one ordinary frame (the latest gap of at most 50 ms; 1/60 s before any) |

-   **No slow motion under jank.** A 1 s animation under 250 ms frames still takes 1 s. RAF timelines stay on the wall clock, in sync with WAAPI, CSS transitions, audio and timers.
-   **No jump after a suspension.** When a hidden tab comes back, animations continue where they paused instead of finishing instantly.
-   **Hidden means suspended, however short.** With the default `visibility: true` the clock listens to `visibilitychange` while its loop runs, so a tab hidden for 0.3 s (below `lagThreshold`) is still a suspension instead of a 0.3 s jump. Detection is event driven: a `hidden` value merely read at frame time never suspends. An idle clock holds no listener; `visibility: false` disables detection, an injected `VisibilitySource` lets tests drive it, and without a usable `document` (SSR, workers) it is a silent no-op. Invalid values throw a `TypeError`.
-   **Pure wall clock:** `lagThreshold: Infinity` applies every gap in full, exactly like WAAPI. This is safe: dynamic springs integrate in fixed substeps and stop once settled, and whole `repeat` iterations are skipped, so even an hour-long gap costs well under a millisecond.
-   **Hard cap (legacy):** `maxDeltaTime` (unlimited by default) caps every delta. A finite value dilates animation time whenever a frame is slower; only set it deliberately.
-   The first update of a timeline that joined a running loop follows the same rule, measured from its `play()`.
-   Invalid values (zero, negative, `NaN`) throw a `RangeError`.

### API Reference

#### `createClock(options?)`

Returns an independent clock (`AnimationClockInterface` plus a read-only `size` and `read(fn)`).

| Option | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `lagThreshold` | `number` | `0.5` | Gaps up to this many seconds apply in full; longer gaps count as one ordinary frame. `Infinity` = pure wall clock. |
| `maxDeltaTime` | `number` | `Infinity` | Hard cap on one frame's `dt` in seconds. A finite value dilates time on slow frames. |
| `visibility` | `boolean \| VisibilitySource` | `true` | A frame gap during which the page became hidden is a suspension whatever its length. `true` uses `globalThis.document`, an object injects a `VisibilitySource`, `false` disables detection (no listener). |
| `requestFrame` | `(cb) => number` | `requestAnimationFrame` | Frame source. Resolved lazily at the first subscribe. |
| `cancelFrame` | `(id) => void` | `cancelAnimationFrame` | Cancels a requested frame. |
| `now` | `() => number` | `performance.now` | Time source in milliseconds, same domain as the frame timestamps. |
| `onError` | `(error) => void` | async rethrow | Receives errors thrown by subscribers. |

#### `AnimationClock`

| Member | Description |
| :--- | :--- |
| `AnimationClock.create(maxDeltaTime?)` | The shared clock. A given `maxDeltaTime` is applied even if the clock exists. |
| `AnimationClock.configure(timing)` | Reconfigures the shared clock: a number sets `maxDeltaTime`; `{ lagThreshold?, maxDeltaTime? }` sets either (validated before anything changes). |
| `AnimationClock.reset()` | Disposes the shared clock; the next `create()` starts clean. |
| `clock.size` | Number of animatables currently subscribed. |
| `clock.subscribe(animatable)` / `clock.unsubscribe(animatable)` | Used by timelines. An `Animatable` is `{ read?(), update(dt), commit?() }`. |
| `clock.read(fn)` | Runs `fn` once in the read phase of the next frame, before any subscriber's `read` / `update`. |
| `clock.dispose()` | Stops the loop and drops all subscribers and queued `read` callbacks. |
