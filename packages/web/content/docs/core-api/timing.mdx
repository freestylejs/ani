A **`TimingFunction`** is a core concept that dictates the speed and acceleration of an animation over its duration. It controls **how an animation progresses from its start value to its end value**, allowing for effects like smooth easing, bouncing, and realistic physical motion.

Timing functions are provided to the `timing` property of an `ani` node.

### Example

```typescript
import { a } from "@freestylejs/ani-core";

// This animation will start slow, accelerate, and then slow down at the end.
const myAnimation = a.ani({
  to: { x: 500 },
  duration: 2,
  // Use a built-in bezier curve for an "ease-in-out" effect.
  timing: a.timing.bezier({
    p2: { x: 0.42, y: 0 },
    p3: { x: 0.58, y: 1 },
  }),
});
```

### Built-in Timing Functions

The library provides several ready-to-use timing functions accessible via `a.timing`.

| Function        | Description                                                              |
| :-------------- | :----------------------------------------------------------------------- |
| `linear()`      | **A constant rate of change**. No acceleration or deceleration.              |
| `bezier(opt)`   | A **cubic bezier curve** for classic easing effects. |
| `ease()`, `easeIn()`, `easeOut()`, `easeInOut()` | The standard CSS easing curves, as `bezier` presets. |
| `spring(opt)`   | A **duration-based**, **closed-form spring** for bouncy UI effects. The whole oscillation is fitted into the segment duration. |
| `dynamicSpring(opt)` | A **simulated spring** for interactive animations. It settles by physics, or at the segment duration, whichever comes first. |

Spring options are `m` (mass), `k` (stiffness), `c` (damping) and an optional `tolerance`.

-   `m > 0`, `k > 0` and `c >= 0` are required. Invalid values throw a `RangeError` when the function is created.
-   The option object you pass is never modified. `c = 0` (undamped) is supported and finite.

---

### `spring` vs. `dynamicSpring`

The library offers two spring functions for different scenarios.

| Feature         | `spring`                       | `dynamicSpring`                           |
| :-------------- | :--------------------------------------------------- | :--------------------------------------------------- |
| **Purpose**    | **Static fixed** animation.        | **Interactive dynamic** animations.   |
| **Duration**    | **Fixed**. The curve is fitted to the duration. | **Bounded**. Ends when the spring settles, or at the duration. |
| **Physics**     | Closed-form curve of time.                            | Simulation with velocity. Can be seeded and retargeted with velocity. |
| **Determinism** | Pure function of time.                                | Pure function of the segment time: independent of frame rate. |

#### A. When to Use `spring`

Use the `spring` timing function when you need a spring-like, bouncy effect that **must complete within a specific timeframe**.

-   **Situation Example:** Animate a modal window appearing on screen. You want it to have a slight "overshoot" bounce, but the entire animation must finish in exactly 400ms.

```typescript
import { a } from "@freestylejs/ani-core";

const modalAppear = a.ani({
  to: { scale: 1, opacity: 1 },
  duration: 0.4, // The animation is guaranteed to finish in 0.4s
  timing: a.timing.spring({ m: 1, k: 180, c: 12 }),
});
```

#### B. When to Use `dynamicSpring`

Use `dynamicSpring` for animations that **react to user input or other dynamic conditions**. It integrates the physics with fixed substeps (at most 1/120 s), so the result depends on the time into the segment, **not on the frame rate**.

-   The `duration` is an upper bound: the segment ends early when position and velocity are within `tolerance` of the target (default `1e-3`), and snaps to `to`. A timeline made only of springs may therefore end **before** its nominal `duration`.
-   `seek(t)` is meaningful: the spring is re-simulated deterministically from the segment start.
-   Playing over a running animation keeps the velocity, so retargeting is smooth. Pass `velocity` to `play()` to seed it explicitly (for example the pointer velocity after a drag).
-   State lives inside the timeline, so one `dynamicSpring` instance can be shared by many segments, properties and timelines.

-   **Situation Example:** A draggable card that can be "flung". On release it springs back with a momentum that depends on how fast it was thrown.

```typescript
import { a } from "@freestylejs/ani-core";

const cardReturn = a.ani({
  to: { x: 0, y: 0 },
  duration: 2, // upper bound; usually settles earlier
  timing: a.timing.dynamicSpring({ m: 1, k: 200, c: 20 }),
});

const cardTimeline = a.dynamicTimeline(cardReturn);

// On mouse up, play from the card's current position with the release velocity.
cardTimeline.play({
  from: { x: currentDragX, y: currentDragY },
  velocity: { x: pointerVelocityX, y: pointerVelocityY },
});
```

> Use `spring` (not `dynamicSpring`) when you need a guaranteed fixed duration.
