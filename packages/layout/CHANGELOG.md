# @freestylejs/ani-layout

## 0.2.0

### Minor Changes

- 3927376: `@freestylejs/ani-layout` 0.2.0: layout animation with a clock-driven RAF engine and an optional compositor engine. Mark an element and it animates whenever a change moves or resizes it, from where it was drawn to where layout put it. This replaces the unreleased 0.1.0 surface as a hard migration: no page boxes, no inner-scroll `'stale'`, no field-by-field motion merge and no legacy bridge or alias.

  - **Default RAF engine.** At each change the group reads every participant's box once before and once after; animation frames do no DOM reads. Every frame computes each moving box from its two ends, parent before child, and writes only `translate` and `scale` (plus `opacity` for a `layoutId` crossfade and `border-radius` when `radius` is on). The default `'raf'` engine is one subscriber of the core clock, so it shares frame time, time scale and reduced motion with every other Ani animation.
  - **Exact nesting.** Nested participants, `layoutAnchor`, shared `layoutId` handoffs and crossfades stay exact at any depth on the default `'raf'` engine. An interrupted element continues from where it is drawn, with its velocity; an element whose target did not move keeps its animation untouched.
  - **Compositor engine.** `engine: 'waapi'` is for top-level `layout: 'position'` participants only: `layoutAnchor`, `layoutId`, `radius: true`, a spring motion and nesting at `add` / `set` throw; nesting introduced later and missing CSS `linear()` support snap as `'unsupported'`. Retargets start from the drawn box without velocity; tracks run on the document timeline, so the Ani clock's time scale does not apply while reduced motion still does; a jank retarget can step back by missed compositor frames. It writes no inline style.
  - **Shared elements.** In a crossfade the new element fades in over the first half and the exiting one fades out only after it, so the pair never shows what is behind it, also when it reverses. The corners blend from the radius the old element showed to the new element's own: `radius` defaults to `true` for an element with a `layoutId`, and `radius: false` on either side turns the blend off. The radius of a resting shared element is read with its box before the change, so a style-only change (a `:hover` radius) is included.
  - **Jump, never move wrongly.** What cannot be animated exactly (rotation, skew, a CSS transition on `translate`/`scale`, too many movers, no valid before-box) jumps to its final layout and is reported as `'culled'`, `'capped'`, `'unsupported'`, `'stale'`, `'reduced'`, `'disabled'` or `'failed'` in `report.snapped` and `onSnap`. `'stale'` means only that no valid before-box existed; a flush with a valid capture never produces it, whatever scrolled. A scroll is measured.
  - **API.** `createLayoutGroup(options?)` returns `add`, `set`, `capture`, `flush`, `update`, `take`, `finish`, `dispose` and `stats`. Options use Motion's vocabulary: `layout` (`true`, `'position'`, `'size'`), `layoutId`, `layoutAnchor`, `layoutCrossfade`, `layoutDependency`, `layoutKey`, `radius` and `motion` (`duration` and `delay` in seconds, a stateless timing or a physical spring). Group options: `clock`, `motion`, `reducedMotion` (default `'jump'`), `threshold`, `maxNodes`, `maxParticipants`, `retain`, `onSnap`, `engine` (default `'raf'`). `flush()` and `update()` resolve once per run with `{ status, snapped }` and never reject; invalid options throw `ANI_INVALID_OPTIONS` synchronously. Motion layers merge by kind (timing or spring); `duration` never switches the kind.
  - **Direct manipulation.** `take(element)` returns a `LayoutDriveHandle` (`state`, `velocity`, `move`, `release`, `cancel`) for a held element. The hold is re-expressed every frame under scroll, an ancestor scale, sticky positioning and re-layout; release carries the incoming origin velocity exactly once. A released/cancelled landing is still a live hold until it finishes or is invalidated. `take` throws `ANI_INVALID_OPTIONS` when the element is not drivable; the gesture layer owns pointer capture, velocity estimation, keyboard operation and announcements.
  - **Runtime and diagnostics.** `layoutRuntime.setMode('snap' | 'animate')` is a synchronous page-wide kill switch, distinct from reduced motion. `layoutRuntime.onDiagnostic(listener)` streams versioned `LayoutDiagnostic` events (`capture-less-flush`, `capture-aged`, `unsupported-geometry`, `handoff-scroll-active`, `spring-timeout`, `participant-cap`, `mover-cap`, `document-mismatch`, `runtime-disabled`, `focus-in-follower`, `drive-rejected`, `reduced-no-fit`, `callback-error`, `internal-error`). Payloads are built only when a listener exists; listeners and `onSnap` are isolated; a failed flush restores every owned style and `inert` byte-identically and resolves `'failed'`.
  - **Presence and View Transitions.** `createPresence` links its element to layout: an exiting element hands its box to the next element with the same `layoutId`, and its release waits for the crossfade. `popLayout` measures the exiting element against its real containing block. `viewTransition`, `shareElement` and `retimeViewTransition` are unchanged.
